# earshot-audio Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `plugins/earshot-audio/` (one skill, upstream Earshot v0.4.0 installed from a pinned commit, real-sound merged in) in this repository's marketplace, and point Studio 1.124.0 at it.

**Architecture:** A standard-library launcher (`scripts/runtime.py`) owns readiness, consented installation with per-file verification, and an allowlisted runner. The skill text carries the behaviour; upstream real-sound files are copied byte for byte and recorded in `upstream.json`. Studio only changes its registry entry and routing wording.

**Tech Stack:** Python 3.10+ standard library (launcher, tests with unittest), git, pip/venv, Claude Code plugin manifests.

**Spec:** `docs/superpowers/specs/2026-10-22-earshot-audio-plugin-design.md`

## Global Constraints

- Upstream pin: tag `v0.4.0`, commit `591fa3e028032e6dce56620a20e932e35667e8d8`, tree `d6f2dbc43f7b38b2147cfd04bbd7aa9055701f1a`, 282 files, MIT, Copyright (c) 2026 Leon Lin.
- Plugin name `earshot-audio`, skill `earshot-audio:earshot`, plugin version 1.0.0; Studio goes to 1.124.0.
- Default runtime root `~/.framecore-studio/extensions/earshot`, overridable by `--root` or `EARSHOT_NATIVE_ROOT`.
- Allowed run commands: `doctor measure describe match rank find compare ab realness timeline sheet critique profile forge fit sfx kit gallery`; `doctor --fetch` refused; `llm`, `mcp` and anything else refused with exit 2 before any process starts.
- Light dependencies: numpy, scipy, soundfile, soxr, librosa, pyloudnorm, scikit-learn, pillow, matplotlib; full adds CPU torch (index `https://download.pytorch.org/whl/cpu`) and transformers. Engine installed with `--no-deps`; extras `mcp` and `llm` never installed.
- No MCP configuration, no keys, no upload; internet recordings only on request.
- Exactly one `SKILL.md` in the plugin. Copied upstream files byte-identical.
- Work on `main`; Studio package paths never deleted or moved; commits carry the repository trailers (Change-ID `CC-20261022-14`).

## Review Focus

1. Upstream adds a new CLI command later: the launcher refuses it (allowlist, not a denylist). Pinned by `test_unknown_command_is_refused`.
2. `--threads=3` (equals form) or `-h` before the command: the real command is still found and checked. Pinned by `test_global_options_in_both_forms_are_skipped`.
3. A source tree that differs in one file from the pin (tampered download, wrong commit): nothing is installed and the venv is not created. Pinned by `test_one_changed_file_stops_install_before_any_write`.
4. `status` on a machine with no venv or a venv whose python is broken: JSON says `unavailable`, exit 0, nothing written. Pinned by `test_status_without_venv_reports_unavailable_and_writes_nothing`.
5. Windows layout (`Scripts/python.exe`): the launcher finds the venv interpreter on either layout. Pinned by `test_venv_python_on_windows_layout`.
