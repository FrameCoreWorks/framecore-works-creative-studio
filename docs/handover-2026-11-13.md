# Handover 2026-11-13: Creative Studio 1.180.0

## What happened

A dependency review of Studio 1.179.0, FrameMotion 0.1.1 and FrameCut 0.1.0 (report: `raporty/2026-11-13-review-studio-framemotion-framecut.md` in the owner's project folder) found 14 problems. The owner approved one repair release of all three (2026-11-13) and added: installing from the terminal brings the whole package, ChatGPT Work installs Studio first and asks about the sub-plugins in onboarding, leftovers of the old modules must be cleaned after an update, the reel workflow (plan, contact sheet, 540p preview, full render) and sound for reels (music and effects from code, a warning before third-party music, about -14 LUFS with the peak below -1 dB, limiting in numpy).

FrameMotion 0.1.2 (`346f867`) and FrameCut 0.1.1 (`865ea35`) were released first; Studio 1.180.0 pins them.

## Changes in Studio 1.180.0

- **Marketplace:** FrameMotion and FrameCut are no longer listed in Studio's marketplace; Studio's entry depends on `framemotion@framemotion` and `framecut@framecut` (cross-marketplace, like Toolbox). Reason: a user who installed one alone and then Studio had two enabled copies (reproduced in an isolated Claude Code 2.1.322 configuration). Open Assets stays in Studio's marketplace (pin 0.8.0): it is asked for, not a dependency, and Studio's setup checks it is readable before offering it.
- **Install guides:** Claude Code and Codex add the four marketplaces and install the whole package; migration rows for `framemotion@framecore-works` / `framecut@framecore-works`; Verify checks the companions and the six welcome options; the clone-timeout variable is named.
- **Cleanup after an update:** `skills/workflow-orchestrator/assets/migration/cleanup_old_modules.py` with `removed-files.json` (built by `scripts/build_removed_files.py` from the 1.153.0, 1.178.0 and 1.179.0 scope records) removes only deleted package files whose bytes equal a shipped version; report first, `--apply` on the user's yes; runtime folders and changed files are kept. ChatGPT Work's private copy keeps 111 runtime paths under the old folders (owner's Work handover 2026-11-13): the tool leaves them.
- **Routing:** pipeline-core, creative-video-producer and the workflow kit no longer name the deleted `hyperframes-workflow` and `remotion-video-production` skills; storyboard-sequence-architect reads the gallery shortlist from the installed FrameMotion.
- **Reels and sound:** studio-contract's control-frames option is the reel workflow; audio-production-director has the music rule for reels.
- **Pins:** Toolbox 1.15.0, Open Assets 0.8.0, FrameMotion 0.1.2, FrameCut 0.1.1.
- **Environment check:** the Animate engine probe no longer reports a working engine as broken because its source list now lives in FrameMotion.
