# FrameCut audit, 2026-10-22

Trigger: the owner asked for a thorough check of FrameCut. Four independent read-only reviews ran against package 1.119.1 (FrameCut engine 1.1.0, ffmpeg 6.1.1, Python 3.13, Linux, 4 cores): real-media workflows, storyboard/gate/editing/effects/jobs, adversarial robustness, and the guidance the model reads. Every finding below marked **fixed** was reproduced before the change and has a test in `tests/framecut_audit_test.py` that fails on the previous code. Findings are agent-reported; items not marked fixed were not independently reproduced by the maintainer unless stated.

Evidence type: sandbox media runs and source checks. Fresh installed-client behavior stays `NOT_RUN`.

## What held up

- Rotation (90/180/270), anamorphic SAR, 10-bit, odd dimensions, VFR with a non-zero start PTS, 24/25/59.94 fps, 4K, an 11-minute source, audio-only and no-audio sources all render with correct picture, audio length and source maps.
- Caption timing within about one frame of the speech; loudness within 0.2 LU of target; export (JSON, relink, CSV, EDL) matches the edit.
- Storyboard panels match the decoded render frames (43/43 in both formats, across ramps, freeze, zoom and framing); coverage is chronological and complete.
- Edits are atomic; `--dry-run` impact equals the applied change; undo, stale-base rejection and locks behave as documented.
- All nine effects work and are deterministic; version pinning rejects bad parameters.
- Job cancel, resume and `kill -9` recovery publish nothing corrupt.
- Path traversal, symlinks, hostile file names, ASS injection, schema bounds, revision races and render-lock concurrency held under attack.

## Fixed in 1.119.2

| Finding | Fix |
| --- | --- |
| `set_captions` replaced the whole object, so `{"size":0.08}` silently turned captions off | A partial value merges into the existing settings |
| A word with no timing was dropped from captions and the SRT, yet the final and caption QA passed | `unknown_timing` blocks a final whenever captions are enabled; the error names the word |
| `analyze` failed on clips shorter than about 16 frames and left a directory that blocked a retry | Thumbnails stay inside the clip; the analysis is built in a temporary directory and renamed |
| `atempo` was always inserted, which moves linked audio about 20 ms early even at 1x | No tempo stage at 1x (other speeds keep it) |
| A committed revision over 16 MiB made the project unreadable, undo included | The limit is enforced on write |
| A caption token that cannot be wrapped crashed after the full encode | Falls back to the unwrapped text |
| Hand-edited `probe.*` values reached `-filter_complex` (filter injection, local file read) | The probe fields are type- and range-checked in `validate` |
| A preview bundle, or one carrying blocking warnings, could be reviewed to `READY` | `delivery_readiness` returns `PREVIEW_ONLY` or `BLOCKED` |
| File names and clip notes with line breaks forged EDL events; CSV cells could start a formula | Control characters are removed in the EDL; CSV cells are prefixed; `note` must be text of at most 2000 characters |
| `export` crashed for non-nominal frame rates and left a half-written directory | A typed error; the export is built in a temporary directory and renamed |
| A source swapped during a render was stored in the cache and later delivered as PASS | The source is re-checked before a stage is stored |
| A render lock left by a killed process blocked every later render with a vague message | A lock whose owner is provably gone is reclaimed; otherwise the message names the lock file, pid and age; SIGTERM and Ctrl-C clean up and print typed JSON |
| `--out` could target the runtime's own files (history, locks, `project.json`) | Reserved paths are refused |
| A project path containing `..` failed with a "symlink" error | The path is normalised before the symlink check |
| A caption font starting with `-` reached `fc-match` as an option | The font name must start with a letter or digit |
| Malformed but parseable documents raised raw tracebacks | Typed errors, plus a catch-all that keeps the JSON error shape |
| Child process limits: the 64 MiB output cap was checked after exit; the timeout error did not say it was a timeout | The cap is checked while the child runs; the message names the command and the limit |
| Ingest could store a probe and a hash from two different files | The file's size and mtime must not change during ingest; an undecodable picture size is rejected |
| Guidance gaps in `opencut-video-studio/SKILL.md`: default render mode, review fields and honesty, `--base-revision` source, fresh `--out`, board needs a compiled edit, English board text, HDR, the 1800 s analysis cap, Linux-only job detection, caption tie-breaks | Smallest text fixes in the owning skill |
| Routing: the 1.119.1 reel sentence also captured "zrób reelsa z nagrania"; cutdown ownership differed between the orchestrator and Pipeline Core; Polish cues for FrameCut were missing | Tie-breaks in the orchestrator table |
| Stale docs: `contracts.md` "draft 0.1", freeze and speed ramps listed as unsupported, an untested editor-import claim, a missing `export` pointer | Corrected |

## Owner decisions (2026-10-22)

- The storyboard stays a host-managed preview shown once for acceptance; further boards only when the user asks. The runtime does not enforce it (items 1 to 3 below are closed by this).
- Music is lowered lightly under speech by default (item 7 is fixed in 1.119.3: -6 dB, following the timed transcript).

The remaining items still wait for the owner.

## Needs the owner's decision (not changed)

1. **The runtime does not enforce the storyboard gate.** `render --mode final` and `job-start` succeed with no board, a stale board or a board for another deliverable; the only precondition is a non-empty `authorization`. The gate is host-managed by design (README, SKILL). Options: keep it host-only with the clearer text now in place, or add a recorded acceptance (board receipt hash plus the user's message reference) that final rendering requires.
2. **Board receipt blind spots.** The receipt carries one whole-project hash and no design or sound content, so changed music, gain or muting leaves identical panels and coverage; no command checks a receipt against the project.
3. **Explicit waiver.** Nothing says what to do when the user says "skip the storyboard". The current rule never treats a request to render as acceptance.
4. **One caption size and `max_words` per sequence**, so one edit delivered in 16:9, 1:1 and 9:16 fails the 9:16 render unless captions are shrunk for all. A per-deliverable override would fix it.
5. **A delivered bundle becomes unverifiable after any later revision** (the fingerprint is whole-project), so multi-format jobs must render, verify and review at one frozen revision. A per-sequence fingerprint would relax this.
6. **Rendering speed**: about 0.1x realtime at 1080p and 0.03x at 4K, because every frame goes through Python/Pillow; preview is no cheaper. A 10-minute 1080p film projects to 1.5 to 2 hours. A 4K clip over roughly 15 to 20 s of output exceeds the default 600 s stage timeout. No performance envelope is documented.
7. **Ducking follows clip extent, not speech**, so a bed under a continuous talking-head cut is ducked through pauses.

## Open, lower priority

- Locks cover a clip's JSON, not its appearance: `set_framing`, `set_deliverables` and an fps change on `set_sequence` pass for a locked clip. `apply --dry-run` omits sequence-level and most deliverable-level changes from its impact.
- Linked audio at constant speeds other than 1x still moves 7 to 25 ms early (ffmpeg `atempo`); constant 2x and 4x do not show `source_in` as the first frame (up to half an output frame).
- `effects --check` cannot fail for picture effects (identity fixtures); audio `denoise` is nearly inert above about -50 dBFS noise.
- A ripple trim is blocked by a full-length music bed or a title spanning the cut until they are re-anchored.
- Job progress counters stay at 0 during picture stages; orphan temporary directories and a SIGKILLed ffmpeg child are not cleaned up; there is no cache-clear command and the disk-budget check runs after the cache is built.
- 1,100 clips fail with `Argument list too long` (`-filter_complex` is passed inline); `compile --out`/`analyze --out` must always be fresh.
- `board_compose.wrap` is cubic in the length of one unbroken word; authored panel fields are untyped; authored panel notes replace the real on-screen copy label.
- SRT and VTT sidecars carry raw markup from caption text; burned captions replace `\`, `{`, `}` with full-width characters, so exact copy containing them is not byte-faithful.
- `unlabelled_color` repeats per clip; the receipt's loudness block mixes measured and hypothetical loudnorm values; the board PDF embeds a creation date; board quotes use Polish-style marks for English copy.
- Creative Video Producer's description and body still say it owns "cutdowns" in the sense of a re-authored variant; the orchestrator table now routes cutdowns of supplied footage to FrameCut.
