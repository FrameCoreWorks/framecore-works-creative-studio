## Ready-to-integrate English subsection for section 11

### Candidate to evaluate: billion-context

[Source snapshot](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/README.md) at commit `dc041dd1ab1a014efa352ba47a6f31fc47f55284` provides context compression around an agent's model requests. It can replace older conversation ranges with model-written summaries and retain material for later retrieval. It does not increase the model's native context window or prove lossless recall. Treat its advertised token reduction as a hypothesis for a specific workload.

For Claude Code, integration is intrusive: [the installer](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/src/plugin-install.ts#L645) edits managed settings, changes model routing, disables native auto-compaction where routing is managed, registers SessionStart/SubagentStart hooks and an MCP companion. [Bootstrap code](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/src/claude-native-bootstrap.ts#L77) explicitly recognizes a Claude Desktop Code-tab bypass condition that can leave native auto-compaction disabled without bili compression. Our installed host has not been tested. Do not infer Desktop compatibility from CLI support.

The [license](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/LICENSE) is MIT text **plus a mandatory product/service attribution term**; manifest MIT labels omit that qualification. [Configuration](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/src/config.ts#L1804) enables automatic updates and separate advisory checks by default; [advisory handling](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/src/advisory.ts#L292) can install a prescribed version even when normal updating is off. Version pinning therefore needs more than disabling one switch.

Propose an isolated, explicitly approved terminal-only evaluation before any admission: synthetic fixtures, no private workspace data, fixed host/model/version, baseline versus compression, complete token/cost/cache accounting, exact-fact and task-success checks, restart/recovery and session-isolation controls. Keep prompts, rules, source files and handover records authoritative outside compressed memory. Reject adoption if protected instructions or source identities change, routing bypasses the proxy, recovery loses facts, or savings disappear after compression/retrieval overhead. No installation or live trial is authorized by this note.

## What the source actually shows

**Observed mechanism.** The [compression core](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/kernel/src/compress.ts#L1935) builds blocks with a supplied summary, covered-message IDs, consumed-block IDs and tier; consumed blocks become inactive. This is semantic summarization with explicit lineage, not an enlarged transformer window. The [content-cache implementation](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/kernel/src/ccr.ts#L454) separately stores qualifying original tool-result text and substitutes a retrievable placeholder, preserving identifiers and tool pairing. Lossless retention of some raw material does not guarantee that the model will request or correctly use it. Those are different claims.

**Documented host routes, not locally verified.** The README lists native or launcher routes for Pi, OpenCode, OMP, DSH, Kimi, Hermes, Zcode, Claude Code and Codex, plus proxy/launcher routes for other clients. Route capabilities differ: its Codex MCP companion alone does not route model traffic. Package metadata requires Node >=20. This review concentrated on Claude; other host adapters were not inspected sufficiently to endorse them. [Host table](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/README.md#which-do-i-need), [package metadata](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/package.json)

**Claude integration details.** The installer targets Claude settings and commands under the effective CLAUDE_CONFIG_DIR, registers user-scope MCP through Claude CLI, and preserves existing unrelated entries with special handling for foreign upstream URLs. It makes a first-write .bili-bak snapshot; that is not a replacement for our dated backups or a tested rollback. Hooks can later repin routing or refresh their managed commands, so installation is not the only write boundary. [Installer, selected sections 459–1082](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/src/plugin-install.ts#L459)

The [MCP entry](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/src/claude-mcp-entry.ts) probes and respawns a failed proxy. Its own comment says a drifted origin can repair settings for the **next** Claude session while the current client retains its startup URL; a watchdog is therefore not a guarantee of immediate current-session recovery. The [subagent hook](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/src/claude-subagent-hook.ts) injects a random lane marker into context; its source explicitly says this is identity routing, not authentication.

## Savings and quality: evidence with important qualifications

**Author claim:** the headline advertises roughly fivefold fewer tokens, small resident contexts and very long sessions. These are not independently reproduced outcomes in this review.

The repository's [third-party-labelled benchmark report](https://github.com/ranxianglei/billion-context/blob/dc041dd1ab1a014efa352ba47a6f31fc47f55284/benchmarks/third-party-1500/README.md) evaluates **v0.1.202**, DeepSeek V4.1 Flash and Pi, not our Claude model/host. It reports ContextBench F1 0.3097 versus full-context 0.2928 with lower stated cost. LongMemEval accuracy is 79.2% versus full-context 83.2%; its 71.1% cost saving uses a counterfactual independent-session baseline, while the displayed actually billed full-context cost benefits from cross-query cache reuse. Its accurate-retrieval task drops from 69% to 27% exact match. Survival at a large context size is not equivalent to correct recall.

The inspected benchmark directory contains narrative reports and chart PNGs, **not a reproduction harness, per-item outputs or raw billing records**. It labels the evaluation independent; this review did not establish evaluator independence or audit the accounting. The claimed 30× context reduction and 5× headline concern different quantities, not a universal Claude cost multiplier. Compression calls, retrieval, cache misses and failed retries must all count in our evaluation. These limitations do not establish the project is ineffective; they make a measured trial necessary.

## Bounded evaluation proposal for Claude — not current authorization

1. **Preflight design:** choose one disposable terminal-only Claude profile; pin this source revision and every material dependency; inventory every intended write, hook, subprocess and egress destination. Keep the real Desktop profile, production sessions and Shared rules untouched. Disable ordinary/advisory mutation, runtime dependency auto-download and optional external summarization in the proposed configuration; verify effective values rather than assuming them. Inspect remaining background requests before approval.
2. **Offline first:** synthetic dialogues and tool outputs only. Define exact original facts, source IDs, quoted strings, revoked instructions and conflicting revisions. Test lossless stored-output retrieval separately from lossy summary reasoning; probe session/subagent separation, restart, missing-store and wrong-key behavior. Do not copy real chats as fixtures.
3. **Only if separately approved, small model trial:** fixed model/effort/host, four tasks × baseline/compression × three repeats =24 runs, with an explicit total budget and stop threshold before execution. Tasks: long repository-style lookup, amended requirements, exact recall, and a multi-step task whose success has objective fixtures. Use fresh isolated state per run and report warm/cold cache conditions separately.
4. **Count the whole cost:** input/output plus cached-input and cache-creation tokens, compression and retrieval turns, tool-schema overhead, latency, retries, disk growth and failures. If subscription accounting hides billed cost, report observed usage—not invented dollar savings. Token reduction and accuracy are separate columns.
5. **Admission gates:** zero wrong protected constraints/source identities, correct recovery and separation, no unauthorized files or destinations, no routing bypass, no loss hidden by an aggregate score. Compare task success and exact recall with baseline before judging net savings. Keep rejected alternatives and failures. Only then prepare a concrete installation/rollback proposal for user approval.

This proposed trial cannot demonstrate month-long reliability or billion-token retention. It can reject obvious incompatibility and quantify a small representative workload.
