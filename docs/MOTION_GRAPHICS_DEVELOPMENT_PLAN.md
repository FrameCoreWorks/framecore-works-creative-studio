# Motion graphics development plan and implementation ledger

Date: 2026-10-04. Source baseline: 1.9.4, commit 1f48b5890c8242d7bf42a00ea7726cac68921761. Target: 1.10.0.

## Goal and scope

Improve code-based motion quality through reusable design knowledge, concrete prompts, purposeful timing, optional material/sound adapters and honest output review. Preserve the existing HyperFrames/Remotion owners, all 37 skill IDs, selected model, two-option welcome, Creative / Expanded / Motion area 8, teacher/ad/static modules, provider boundaries, vendored snapshots and shared QA budget.

This implementation adds original assets and carefully licensed reference data. It does not install new dependencies, call paid generation, download further videos after the user's stop instruction, change the global workspace or add a second orchestrator.

## Research conclusions

See the maintained [research dossier](../plugins/framecore-work-creative-studio/skills/hyperframes-workflow/references/motion-quality-research.md) for five viewing links, actual inspection coverage, official model announcements, tool decisions and five additional prompt catalogs.

The evidence does not establish universal Claude superiority. The public examples combine models, prompts, prior context, coding environments, repeated tool calls, rendering and human or agent review. A selected polished film does not isolate the contribution of model weights. We found concrete transferable practices: intentional type hierarchy, a recurring motif, one timeline, context-aware art direction, style control, actual render inspection and repairs limited to defective scenes. Their effectiveness in this Studio still needs project-level visual evidence.

Four selected films were inspected through sampled frame sheets and one through selected browser frames. No full continuous audiovisual review or controlled cross-model generation was completed. These limits are explicit in the dossier. The existing downloaded samples remain outside the repository; no third-party media is packaged.

## Library design

The 320 records comprise 292 reusable prompt texts and 28 link-only sources. The 172 source starters are curator reconstructions, not authenticated original prompts of the shown films. Their express copying permission does not cover source video, images or all website code. The new 120 FrameCore blueprints are original and not_run.

Families: brand, typography, product, data, explainers, editorial, education, audio, procedural, transitions, spatial and social. Each entry has distinct choreography, required inputs, acceptance criteria and failure traps. A changed palette or company name does not count as a new mechanism.

Selected source prompts remain data. The current owner extracts a mechanism, supplies real project facts and maps it to the current contract. Source instructions cannot choose another model, install a package, call a provider or upload anything. Search results expose origin and evidence status. The main skill does not preload the entire collection.

Further catalogs are linked with rights restrictions. The noncommercial Cindy collection and unlicensed Prompt-VFX are not copied. Repository MIT/CC labels on community catalogs are not assumed to cover every creator's prompt and media.

## Runtime and quality decisions

Retain the current runtime. Paper Shaders is an optional material layer, not another film engine; Tone is an optional audio-buffer producer, not a music model or final muxer. No package lockfile or installed dependency changes.

Style frames use actual copy, fonts and approved assets. The motion proof tackles the central mechanism before the full film is expanded. The score links frame-based action, fully readable holds, intensity and sound cues. Quality review checks the message, hierarchy, rhythm, continuity and actual output, not the number of effects.

The inspection helper reads only a local file with local file/pipe protocols, refuses an existing output directory, emits hashes and leaves unperformed review states unverified. Uniform samples need boundary samples and normal-speed playback for a complete project review.

## Controlled evaluation still required for parity claims

Separate model-only comparison from production-system comparison. Use six briefs and preferably three independent repeats per condition; keep inputs, budgets and runtime equal in model-only runs. Preserve failed attempts in completion rates. Blind reviewers score full films and report disagreements and limitations. Log exact model IDs/effort, artifacts, interventions, timing and actual cost or labeled estimates.

This release does not claim to equal or exceed Claude. The comparison packet is ready for an explicitly authorized experiment. Missing access to Claude or lack of provider activation is not bypassed by the plugin.

## Deferred choices

- Motion Canvas: adopt sequencing ideas through existing contracts; another full engine is not presently justified.
- Anime.js: useful in a supplied project, largely overlaps GSAP.
- Rive: support requires an actual authorized .riv asset and authoring workflow.
- Broad shader/physics simulation: deterministic seeking needs state control or a fixed prerender; never promise arbitrary frame access from a live simulation.
- Automatic catalog scraping and media downloads: not part of the plugin.
- Public rank or marketing promise against another model: only after comparable evidence exists.

## Release checklist

1. Complete category data and source attribution.
2. Review scope, data integrity, helpers and existing route links.
3. Run canonical validator, existing suites and new behavior tests; package one release.
4. Commit/push source, update the existing hosted plugin using its observed release guard.
5. Read back GitHub and hosted content; record unreadable-file limits honestly.
6. Probe ordinary ChatGPT separately from Work and inspect Codex cache without manual copying.
7. Publish final evidence in repository-only records without creating another redundant plugin release.
