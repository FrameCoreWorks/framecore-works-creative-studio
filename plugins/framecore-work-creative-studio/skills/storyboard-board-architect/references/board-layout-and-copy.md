# Board layout and exact copy

This reference governs the static board as a designed page: panel selection,
layout, hierarchy, labels, readability, and exact strings. It synthesizes
selected Visual Prompter K15/K18; Video Prompter K14/K15/K18; Storyboard &
Reference Board Creator ROOT/META/K01-K04; and pinned Workflow Kit
`storyboard-board` contracts/examples. It is not a fixed template catalog or a
claim that a prompt renders typography correctly.

Related contracts: [sequence and continuity](../../storyboard-sequence-architect/references/sequence-contract-and-continuity.md),
[reference authority and carriers](../../storyboard-sequence-architect/references/reference-authority-and-carriers.md),
[delivery and handoffs](board-delivery-and-handoffs.md).

## 1. Establish the board's job

Before drawing a grid, state what the page is meant to help someone decide:

- review story order or rhythm;
- compare selected visual moments;
- communicate scene geography and coverage;
- align stakeholders on a look or character reference;
- hand a set of shots to production or image/video prompt work;
- inspect an existing board and identify a specific structural defect.

These goals use different panel selections. A rhythm board can emphasize
temporal contrast; a camera coverage board can group by scene; a reference
board can place one large identity/source image beside smaller studies. Do not
fill panels just because the page has room. Conversely, do not omit a shot
that the user required merely to preserve an attractive grid.

Classify the purpose before requesting inputs:

| Purpose | Required content authority | Order and timing |
|---|---|---|
| Temporal story | Supplied/selected events, shot identities and source revision, or explicitly provisional story choices | Preserve intended event order; timing only when needed and sourced/estimated explicitly |
| Coverage comparison | Subject/state being compared, useful views and property locks | Comparative grouping; no invented event progression or duration |
| Reference | Actual sources or authorized design proposals, roles and selected properties | Group by comparison purpose; no sequence, shot plan or timing prerequisite |

Resolve only material inputs: purpose-appropriate source/version; selected
moments, views or properties; panel count if known; viewing context/size; exact
labels and language; reference roles; and specification, prompt, generation or
inspection intent. A clear brief may proceed without a full form. Optional
panel IDs support internal mapping; they do not authorize extra visible text.

## 2. Choose a layout from content, not habit

A 3x2 contact sheet, a 16:9 landscape page, and a 4:1 horizontal strip are
examples only. They are neither universal defaults nor evidence-backed
requirements. Select layout by:

1. number of selected panels and whether each is equal or has a hero frame;
2. reading path and meaningful temporal or comparative grouping;
3. label/caption length and needed type size;
4. target display/print context and viewing distance;
5. aspect ratio of each panel's actual image content;
6. safe margins and space for a title or production notes, if required;
7. whether the sheet will be read alone or alongside a separate copy deck.

Useful families include a paced single row, two-row sequence, asymmetric hero
plus supporting frames, grouped scene bands, paired before/after states, a
reference matrix, or multiple paginated sheets. These are design options, not
presets to impose. For many panels, split into pages or scene groups rather
than shrinking every cell to illegibility. For one key moment, use a keyframe
sheet only if that is the requested artifact; do not call a lone image a
multi-shot storyboard.

Panel dimensions can vary deliberately to express hierarchy, but panel size
must not falsely imply that one shot is approved over others. If selected
moments are alternatives, label the set `Option A/B` or similarly exact copy
only when supplied/approved. For temporal boards, stable shot IDs map to
sequence cards even if panel placement differs. For reference/coverage boards,
map each panel to its source, property or view; do not require fictional shot IDs.

## 3. Composition inside each panel

Each selected image should make the stated moment legible at the intended
scale. Preserve its approved subject, action, screen direction, camera
position, and required background relationships. Cropping is allowed to
serve board hierarchy only when it does not remove the evidence the panel is
meant to communicate. For instance, a panel intended to compare entry
direction needs enough geography to see that direction.

Avoid redundant panels that contribute no comparison or planning value.
Repeated composition and a locked camera are intentional when they isolate a
change in action, expression, costume, light or material. Preserve that comparison
rather than imposing different angles. Distinct shot sizes and viewpoints come
from approved coverage only when that purpose calls for them. Temporal panels
must not add events absent from the accepted sequence. Non-temporal panels need
no story event. An illustrative panel may be an authorized design proposal;
label its interpretation provisional when not yet approved.

Use a quiet but intentional framing system: consistent panel edges/gutters,
deliberate alignment, coherent crop treatment, enough breathing space, and a
clear relationship between image and label. Do not add film sprockets,
clapperboards, fake timecode, lens specs, faux UI, random arrows, red grease
pencil, or distressed paper just to make it look like a storyboard. Add marks
only when they communicate a real production decision.

## 4. Exact visible copy is a locked asset

Create a copy inventory before finalizing a board prompt. For each string,
record ID, exact text, purpose, location/panel, language, mandatory status,
approval status, and whether line breaks are flexible. Examples include:

- board title and project/sequence identifier;
- shot numbers/IDs;
- scene names, duration or time ranges;
- short approved action labels;
- selected dialogue or sound cue;
- legend, option label, or production note.

Preserve every supplied and approved string character-for-character, including
diacritics, punctuation, case, quotation marks, numerals, and separators. Keep
the conversation in the user's language; do not translate exact visible board
copy as a side effect of compiling a technical prompt in English. Do not
invent title, credits, version numbers, dates, camera/lens metadata, brands,
or explanatory microcopy. An uploaded script or image may contain text that
is not approved for display; ask or omit instead of treating every visible
string as copy.

Line breaks are a separate decision from wording. Reflow only when allowed;
do not insert hyphens, alter punctuation, drop a condition, change decimal
separators, or paraphrase to fit. If mandatory text exceeds space, resize or
re-layout, use a companion copy deck/specification, or ask permission for a
different exact label. Do not silently shorten it.

## 5. Typography and reading hierarchy

The reader should decode, in order: board purpose/title if needed, panel/shot
identity, image, then supporting note. Do not let labels compete with the
frames. Use a small coherent type system with distinct roles and adequate
contrast; avoid treating every label as an equal headline or using many
unrelated type styles to fake sophistication.

Check at actual intended presentation size, not only while zoomed in:

- Can the panel order be understood immediately?
- Are IDs and their associated captions clearly paired?
- Do similar IDs or long strings remain distinguishable?
- Can the smallest mandatory line be read at the expected view distance?
- Does the board still make sense if a tiny decorative detail disappears?
- Is color contrast sufficient without relying on hue alone?

If a text-heavy technical deck cannot be legible as a single raster image,
separate the concise visual board from a copy/deck specification. Describe
which exact text belongs where; do not claim image-generation systems will
reproduce arbitrary long fine print perfectly. Any factual timing, camera, or
continuity metadata must come from an approved source, not graphic garnish.

## 6. Safe area and visual structure

Keep title/labels and key image content within a deliberately chosen safe
area. Leave enough page edge and gutters for the expected viewing/export
context; do not claim print bleed or production dimensions unless supplied and
verified. Every label should have room to breathe and stay attached to its
panel. Avoid accidental tangent alignments, inconsistent label anchoring, and
crowded corners. For dark or cinematic board treatments, ensure small text
and dark frames do not collapse together.

The board should expose a clear information hierarchy without over-design:
the image content carries the moments; labels disambiguate; a restrained
title/legend supports navigation. Background texture or color should not
reduce contrast or imply an unapproved style direction. Repeated decoration
does not make the concept more authored.

## 7. Board prompt construction

When a prompt is requested, compile a standalone description of:

1. artifact type and its intended use;
2. exact page proportions and intended output only if resolved;
3. panels in the intended reading/grouping order, with approved moments for
   temporal boards or selected views/properties for coverage/reference boards;
   shot/panel IDs only when relevant, and no unrequested visible labels;
4. panel hierarchy, grid logic, spacing, margins, and reading direction;
5. exact visible copy per panel, with language and copy lock;
6. references and their property roles, plus features not to transfer;
7. typographic hierarchy, contrast, legibility, and omissions;
8. one observable board acceptance test.

Do not claim JSON/YAML is native syntax unless current generator/surface docs
confirm it. The prompt compiler, not this stable board craft, chooses model
syntax and verifies current capabilities. A prompt-only request ends with a
prompt/spec, not a generated board or assumed user consent. If generation is
explicit, use only an actually exposed and authorized host tool. If no tool
is available, say so and preserve the production specification.

## 8. Inspect a supplied board

Only diagnose an image that is actually available. Identify what is visible,
what was not checked, and whether it is a full image or a partial capture.
Check wrong/missing panels, label mapping, order, exact strings, crop, source
authority, hierarchy, legibility, margins, contradictions, and whether the
board invents content beyond its temporal sequence or reference/coverage brief.
Distinguish a board artifact error from a sequence error where applicable: a misplaced panel may need layout repair;
an impossible action may need sequence revision. Do not rewrite all shots to
fix one misaligned label.

## 9. Board quality loop

For each material issue record: observed evidence; specific panel/region; the
accepted elements to preserve; one principal correction; and a test. Example:
“S04 label is paired with panel S03; preserve the image crops; move the label
to the S04 card; pass when all four IDs match the sequence.” Re-run relevant
copy, authority, order and readability checks after a coupled correction.
Do not claim the board is production-approved just because the prompt/spec
passed a textual checklist.
