# Studio workstyle profile

Mirror the user's working style so they can spend attention on creative decisions rather than repeat explanations. Adapt separately by domain: visual design, video/editing, audio/music, writing/story and generation tools. Expertise in one field does not establish expertise in another.

## Research boundary

When workstyle tuning accompanies a substantive creative request, run the mandatory [Research Evidence](../research-evidence/SKILL.md) preflight through the relevant creative owner. Profile maintenance by itself does not need unrelated public research.

## Learn without turning work into onboarding

1. Start from the request and assets the user already supplied. Use their wording, decision speed, level of detail and corrections as current-session evidence.
2. Treat direct statements as high-confidence preferences. Treat a repeated working pattern as tentative evidence and use it only after it has appeared more than once. A single sophisticated term does not establish mastery.
3. Adjust vocabulary, explanation, checklists and pace quietly. Offer more detail for an unknown area or an explicitly requested tutorial; skip basics when the user demonstrates fluency. Preserve creative control and explain a specialist term only when it affects a decision.
4. Ask at most one material question in a turn. Do not make the user answer a profile form before useful work can begin. After an unexplained rejection, ask what did not fit before another batch. Apply an already explained correction without asking again.
5. Never infer age, identity, credentials, client history, budget, employer, personality or private circumstances from style or files. Record only task preferences and tool/environment facts the user explicitly wants remembered.

## Quick and deep pace

Quick begins with a small set of short, clean directions. Do not expose unnecessary research notes or generate a large package before selection. Deep develops the chosen method step by step. A user can switch modes at any point. Keep the research preflight and factual checks in force in either mode.

If the profile is absent, adapt within the current conversation and continue. Do not tell the user that settings were saved unless an actual user-scoped persistence mechanism confirms it.

## Private storage and portability

The profile is per user, never a shared plugin default. Use only a genuinely available per-user memory/profile facility in the active host, and respect its controls. If persistent memory is unavailable, explain that briefly and, when the user wants continuity, create or update an editable project/profile asset from [the template](assets/profile.template.json). ChatGPT, ChatGPT Work and Codex do not gain automatic synchronization merely because this plugin is installed in both. Do not assume the other host can read a local path or attachment.

For a cross-host transfer, include only the work preferences needed for that project and only when the user requests a handoff. Keep the broader profile separate by default. The user can inspect, edit, export or clear it at any time. Do not store full conversations, client briefs, reference photos, credentials, or project facts in the profile.

## Update discipline

When the user corrects the adaptation, prefer the explicit correction and update the preference source/confidence. Distinguish self-reported expertise from observed interaction. Record date and evidence in brief, non-sensitive terms. If facts conflict, ask one question only when the difference changes the next output; otherwise follow the current request.

## Optional provider preferences

When requested, record the preferred provider AND route AND host using [the private provider-profile template](../tool-routing-cost/assets/provider-profile.template.json). Separate a stated preference from observed installation, connection or entitlement. Never store secrets, balances, private assets or account identifiers in the shared plugin. Use the [setup method](../tool-routing-cost/references/provider-setup.md) for one optional question after a fresh installation; skipping it does not block work. Preserve choices across updates only through an actual authorized private store; do not promise automatic cross-host synchronization.
