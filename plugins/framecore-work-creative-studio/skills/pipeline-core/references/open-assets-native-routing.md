# Open Assets, Earshot and Studio

Studio owns the brief, reference roles, master timeline, approvals and final review. The separate `framecore-open-assets:open-assets` companion owns external asset discovery, permitted transport and provenance. The separate `earshot-audio:earshot` companion owns audio processing and measurements. They hand off evidence, never delegate the whole project back to each other.

1. Resolve each installed skill from the current host catalog and read it. A file in a package or a successful test in another host does not establish activation. If missing, name the gap and offer the host's supported installation route; an already authorized setup needs no repeat consent. Without code/network, give a plan and mark execution NOT_RUN.
2. Open Assets runs its own `scripts/runtime.py status`; selects only documented, tested provider/category paths; then searches and uses `verify` for the first actual asset here. A PASS from Work does not certify Codex or Claude. Never call Openverse or substitute scraping, cookies or an unapproved source.
3. Retain the actual file plus `.asset.json`: provider/item, source page, creator, exact licence URL, attribution, selected rendition, SHA-256 and decode evidence. Keep unknown, NC/ND, unaccepted SA, NASA/jurisdiction review and technical-only outputs out of production. A provider transport PASS never clears all its catalogue.
4. For sound, Earshot checks `scripts/runtime.py status --json`. `ready_light` supports measurements; neural selection requires `ready_full` and actual model execution. Import the existing audio using its `real-sound/scripts/import_open_assets.py`; it checks bytes and Earshot's narrower rights policy, writes the sound manifest and optionally a Studio asset manifest. No second download. The agent reads the source licence and records the audit evidence; the importer does not invent that review. SFXMint audio is synthetic library audio.
5. Earshot measures/audits the file, returns hashes, readings, credits and cue evidence. Studio validates the optional manifest with delivery-documentation's `scripts/asset_manifest.py check`, then merges it into the project graph without replacing existing assets. Imported records remain `not_reviewed` until actual creative review; no fake delivery acceptance. Processed audio gets a new revision/hash linked to its source and rational-FPS cue mapping.

On a missing skill, policy hold, challenge, quota, decoder error or unsupported category, report the exact failed stage and ask before changing source or route. Retain successful assets. Do not restart intake, silently generate replacements or upload assets. Provider/client availability, saved-package synchronization, tests and the final creative result are separate facts.
