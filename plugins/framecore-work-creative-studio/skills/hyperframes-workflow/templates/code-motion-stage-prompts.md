# Three stage instruction packets

Adapted from the user's storyboard/build/review example to Studio's existing owners, state and QA budget. Select only the requested stage. Fill actual contract/asset references; instructions do not prove approval or execution.

## 1. Brief and storyboard

Act as the existing motion direction and sequence owners. Inspect supplied context and accessible assets. Reuse approved decisions; mark facts Confirmed, Proposed or Unknown. Ask only the next consequential missing question under Studio's workstyle rules. Keep learning onboarding sequential. Do not code or generate assets at this stage.

Establish objective, audience, message, format, FPS, duration, exact copy, authoritative assets, sound or silence, deliverables and restrictions. Inventory asset IDs, revisions and availability. Separate inspiration from approved source art.

Develop one visual mechanism tied to the message. Set composition, hierarchy, numeric margins, palette, type and motion behavior. Record Creative DNA and a Style Lock where helpful; keep them inside this contract. Do not impose a stock aesthetic or mandatory CTA, voiceover, bounce, 3D or camera move.

Create a versioned storyboard with stable scene IDs, purpose, exact copy, asset IDs, entry/action/exit states, composition, motion/easing, persistence, transitions, fully readable holds and audio cues. Use one master timeline, integer N, frames 0..N-1 and [start,end) intervals. Resolve incompatible duration/FPS with an explicit proposal. Account for overlaps without increasing duration.

Define at least three observable concept criteria plus hard copy/asset/timing requirements. Deliver the brief, visual/motion system, storyboard, asset gaps and compact handoff. Request approval for the proposed revision before first implementation. Never claim approval or measured render timing that does not exist.

## 2. Build the approved motion

Act as the selected existing runtime owner. Identify the latest approved contract and its evidence. Preserve concept, copy, assets, scene order, Style Lock and user edits. Do not restart onboarding. Resolve only blocking conflicts and continue unaffected work.

Inspect the actual project, package manager, available runtime, fonts, media, scripts and export requirements. Reuse existing versions. Choose the simplest available compatible engine if no runtime is locked. Do not add dependencies or install tools without applicable authorization. Missing tools or assets must be visible blockers.

Centralize tokens, copy, timing, assets and render settings. Derive scene state from the requested frame with one master timeline. Use the same scene logic for preview and export. Provide play/pause, replay and exact-frame seeking where preview controls are available. Avoid state accumulated from playback, uncontrolled clocks and unseeded randomness. Wait for fonts/assets before capture.

Preserve approved artwork and exact wording. Separate supplied logo parts only when authorized. Implement audio cues/gain/fades or intentional silence. Recompose each requested aspect ratio; do not silently crop required content.

Run only authorized, available local preview/render operations. Inspect first/last frames, text holds and transition boundaries; compare replay/direct/backward seeking. Watch normal-speed output and listen when possible. Inspect encoded dimensions, FPS, frame count, duration and required audio/alpha. Record limitations independently.

Deliver editable source, actual exports if produced, exact supported commands, versions, edit locations, Delta/Verification/Notes and separate project/creative/export readiness. Never equate preview with export or install/generation/publishing with a planning request.

## 3. Review, repair and final QA

Act as the existing runtime/domain reviewer within Studio's shared QA loop. Identify approved contract, source revision and exact render. Preserve successful scenes and a recoverable baseline. Missing evidence is NOT VERIFIED.

Inspect full normal-speed playback and required audio when accessible, plus frame 0, N-1, holds and transition boundaries. Review concept/message, hierarchy, pacing, continuity, purposeful motion, exact typography/diacritics, margins, protected assets, ending/loop, audio and technical export. Use supplied or verified platform specifications.

Compare selected frames after replay and direct/backward seeking. Inspect the encoded file itself. Static frames, code and metadata cannot establish full audiovisual quality.

Separate defects from preferences. Record scene/frame, criterion, expected/observed behavior, severity, cause and smallest repair. Fix critical/major issues first while preserving duration, copy, geometry and other locks. If a lock must change, present the concrete proposal and wait for approval.

Recheck repaired areas, adjacent transitions and the final revision. Reuse the existing pass count: first review plus at most two repairs/reviews; stop on acceptance or the shared limit. No new loop after a handoff.

Deliver Delta, an evidence table with PASS/FAIL/NOT VERIFIED and justified N/A, unresolved issues, file/settings information and separate project, creative/temporal, audio and export readiness. Do not publish, upload or call paid services from this packet.
