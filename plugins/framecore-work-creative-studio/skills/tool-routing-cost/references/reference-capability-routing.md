# Route reference work by verified capability

Use when the task depends on identity, multiple sources, a board or a starting frame. Respect the user's chosen provider. Do not redirect merely because another model is familiar or has a higher advertised reference count. Read [current-source evidence](../../research-evidence/references/reference-audio-expansion-sources.md) and use the existing [execution contract](execution-adapter-contract.md) when actual execution is requested.

## Compare the operation, then the surface

Record task, modality, exact operation, reference roles, number of required attachments, user-selected provider/model and actual host surface. Distinguish a provider website, official API, third-party wrapper and a native host image tool. Their model names, controls, limits and attachment handling may differ.

Evaluate required capability before optional polish:

| Need | Evidence to verify | Insufficient evidence |
|---|---|---|
| One real person's identity | Documented reference conditioning for the exact operation, actual bound identity source | A model name or a marketing portrait |
| Several people | Multi-subject/reference handling and explicit alias-to-person roles | Total image-slot count alone |
| Garment plus identity | Separate source roles and how the target accepts them | Repeating a long outfit description |
| Precise product | Input editing/reference support and preservation limits | General photorealism claims |
| Storyboard sheet | Layout/text behaviour, useful output size and target frame needs | Ability to generate one attractive image |
| Image-to-video continuation | Supported starting/end-frame or video reference mechanism | Assuming a sheet is a video input or that an earlier chat attachment is reused |

Use [the capability card](../assets/reference-capability-card.template.json). Documentation establishes supported operation; actual inspected outputs establish observed quality. Record a user's provider preference as a preference. Do not convert an anecdotal experience into a universal model ranking, or claim that all realistic people must use one particular generator.

## Dated examples of why surface mapping matters

On 2026-09-28, Runway's Gen-4 Image References guide describes up to three active references and recommends clear, evenly lit character inputs with neutral expression. Google's Gemini image guide describes a larger total reference budget, with different character/object capacities by model and limitations for its Lite variant. Those are provider-documented capabilities, not a comparative realism benchmark and not a promise that this host exposes either route. Recheck the exact version before compiling current parameters.

Do not treat Nano Banana 2, Nano Banana Pro, a similarly named wrapper and the conversational language model as interchangeable. When a name is unclear, resolve the exact target only if it changes the requested output. A conservative standalone prose prompt can remain useful while an API schema is Unknown.

## Resolve constraints without silently losing fidelity

If the reference budget is insufficient, retain the strict requirement and show the concrete conflict. Consider only user-compatible paths: remove redundant references, bind the relevant source subset per shot, use an approved intermediate carrier, or offer a capable alternative. Packing many faces into one sheet is not automatically equivalent to native multi-reference support. A generated intermediate needs inspection and selection; its existence does not prove identity.

Prompt-only work can describe the binding requirements without upload. Execution requires actual input access and scoped authorization. Do not upload private material to obtain a capability demonstration. Do not run comparative paid samples as routine model selection. If required capability is unsupported, stop that execution branch and preserve the usable plan.

## Keep the card fresh

For mutable controls record the official source, retrieval date, exact model/version and interface, supported/unsupported/Unknown state, and what would make the decision change. Exclude unsupported seeds, sliders, reference weights, masks, duration flags or JSON keys. If documentation and wrapper disagree, follow the callable wrapper contract for execution and state the limitation. Never silently send an unsupported field or change models after an error.
