# Optional Hallmark support for coded pages

Use for a new coded website/app-screen task when Hallmark would help, or when the user names Hallmark. For an existing design, invoke native Hallmark only when the user explicitly names it for audit/redesign; otherwise use Studio's own bounded review and preservation method. Existing Graphic Design remains the owner. Read the [reviewed integration](../../../integrations/hallmark/README.md) and its entry in [FrameCore Works Toolbox](../../workflow-orchestrator/references/extensions.md#toolbox-catalog); invoke the actual native `hallmark` skill only if discovered and readable. A recommendation or imported reference is not an installed tool. Reuse existing installations and their declared dependencies.

## Reusable method

1. State the visitor's task and necessary next action from the brief. Inventory actual product material, proof, copy and missing assets through existing owners. Choose page anatomy around that task; do not force a hero/marketing layout onto an app or component.
2. For a redesign, record the existing accepted copy, claims, links, form fields, handlers, routes, IDs and test hooks before editing. Preserve behavior and accepted brand locks. Hallmark's `sloplint --before` and `--kept` can compare its observable inventory; still inspect important interactions with the host's actual browser/testing tools.
3. Inspect the first viewport at agreed desktop and mobile dimensions before extending the composition. Check the task, action, typography, crop, hierarchy and real proof. For an app, inspect the relevant task state. Then check the whole deliverable.
4. Separate functional/accessibility/claim defects from aesthetic heuristics and finish notes. Fix objective defects; explain any chosen style exception. A lint score or screenshot cannot certify usability, accessibility, originality or publication readiness.

## Studio authority and runtime

Reuse the existing brief, brand, exact wording, permissions and QA budget. No second questionnaire, new approval window, universal ban on gradients/caps/illustrations or forced random theme selection. Select upstream theme/reference material only when it serves the accepted direction. Native full resources remain available independently; no new Studio owner or motion engine is introduced.

Static lint requires Node; browser checks need Puppeteer and Chrome/Chromium. Discover existing local components, including the host's component README, before installing dependencies. Run the actual native script and retain its command, result, target revision and screenshots. Read/inspect rendered evidence before saying it was reviewed. If the render tier did not run, report static-only evidence and the concrete missing prerequisite. Installation, discovery, static lint, browser run and human/model inspection are separate facts.

Presence of `TOGETHER_API_KEY` is not permission for paid generation or transferring private input. Reuse authorization already given for a concrete task; obtain a missing scope only when needed. Third-party photo/font rights and selected source attribution remain independent of Hallmark's code licence.
