Use [native Superpowers support](../pipeline-core/references/superpowers-native-routing.md) for consequential layout/composition decisions, multi-step coded implementation, reproducible typography/overflow faults and completion evidence. This owner retains visual hierarchy, exact copy and image-edit routing; ordinary raster work does not become a development project.

For multi-format variants, photo batches, retouching recipes, local font specimens, templates or mockups, use [account-free production](../pipeline-core/references/account-free-creative-production.md). Inspect source properties, protect exact copy and brand regions, review representative previews before propagating a new look, and export from originals. This route never requires an Adobe account or Adobe services.

Before final delivery of a substantive authored, revised or generated creative artifact, automatically apply [output review](../pipeline-core/references/loop-protocol.md#automatic-output-review). Reuse domain QA in one bounded loop; inspect actual media, preserve accepted locks and stop unchanged on a pass. This does not run for greetings, menus or onboarding questions. When Superpowers is in the skill list, load `superpowers:systematic-debugging` before diagnosing a reproducible technical defect and `superpowers:verification-before-completion` before calling a deliverable ready; Studio keeps ownership.

**Out of scope first.** If the request belongs to another owner, load that owner's skill and continue there; do not produce its deliverable here. Anything that moves (an animated banner, a GIF, a reel) goes to [Motion Graphics](../hyperframes-workflow/SKILL.md) for coded motion or [Video Prompt](../video-prompt-architect/SKILL.md) for a generator.

## Work mode and selection

**Fresh directions.** Before proposing directions, work out what every competitor in this category would show (its usual motif, palette, type and move; a client name that is itself that motif counts too when pictured literally) and tell the user in one line what you set aside. Build each direction from material that belongs to this client (how the thing is made or used, a place, a habit, the name) through a different lens (a process, a consequence, an absence, a borrowed format, the name), so the three differ in mechanism, what changes and why, not in palette; at most one may use the defaults, labelled as the classic, and the look follows the idea. Method: [ideation method](../pipeline-core/references/ideation-method.md).

- **Quick:** first return a few materially distinct, concise directions (normally 2–4, or the requested count), found with the [ideation method](../pipeline-core/references/ideation-method.md). Keep each to a short concept/copy/image relationship. Do not return a research essay, production prompt pack, storyboard or generated image before the user selects a route, unless they explicitly requested those artifacts now.
- **Deep:** explore the communication problem, audience response, concept and wording step by step. Build only the next decision the user needs; do not dump the entire production package before a direction is settled.
- Both modes use the Studio's conditional public-research gate for substantive creative decisions: research runs only when a trigger applies. Quick keeps triggered research behind the scenes and returns clean ideas first. Search only generalized, non-confidential questions. Extract a mechanism or craft decision and make an original direction; do not copy a layout, distinctive image/copy, prompt or living creator's style.
- After an unexplained rejection, pause before another batch and ask one narrow question about the missing dimension. Apply an already explained correction directly without asking again. Preserve choices and rejections as local to that user's project.
- Keep the upstream approval gates: a request for concepts, copy or a prompt is not permission to render. Do not fabricate unsupported text, logos, product claims, accessible controls, native tool settings or output QA.

## Exact text for client finals

Visible text has two routes: one-pass generation for concepts and art-led lettering, and [exact-copy compositing](references/exact-copy-compositing.md) for finals whose price, date, address, logo, legal line, small text or print files must be exact. Name the route in one sentence; the user's choice wins. The [static compositor](assets/static-render/README.md) sets the copy in a [bundled font](../pipeline-core/assets/fonts/README.md) or the user's licensed font, at the exact size or print size with bleed, and stops instead of cropping. Where the pinned upstream method or a workflow-kit file forbids adding text after generation, that rule governs the one-pass route; this named route is the agreed exception.

## Vector wordmark

Where Python with fontTools and Pillow runs, set an approved wordmark as outlined vector paths with `scripts/svg_wordmark.py --text "…" --font archivo/Archivo-Bold.ttf --language pl --out-dir logo/`: the font's own kerning and Polish letterforms, colour, black and white SVG files without live text or embedded raster, PNG renders, a preview with clear space and small sizes, and a report with the font licence. It is a starting point set from a typeface, not a custom drawing or a trademark search; refine letterforms in a vector editor when the brand needs its own. A symbol stays a separate design task.

## Logo concept and craft pass

For a new logo, redesign or logo critique, adapt the [reviewed Logo Design method](../../integrations/logo-design-skill/README.md) within this owner and the existing brand-identity profile. Reuse the brief and approved direction; preserve the requested medium and generation permissions. This method does not select SVG or another renderer for the user.

- **Preserve recognition in a redesign.** Identify which existing features carry recognition, which cause the reported problem and which may change. Agree the scope of correction before replacing distinctive geometry; do not turn a refresh into an unsolicited rebrand.
- **Find the identifying idea.** Connect a concrete fact about the brand, name or use to a visual relationship; describe it in one sentence. Explore genuinely different constructions or mark types when alternatives are requested. Judge clarity, fit, distinction and survival at the intended size before polishing. Avoid a catalogue of services in one symbol, mandatory concept counts or copying a familiar mark.
- **Prove the shape before decoration.** For new concepts, inspect a one-colour version before using colour or effects to sell the idea. Show comparable concepts at the same scale, with a brief recommendation and an honest weakness. Follow the existing selection checkpoint; a previously selected direction or an explicitly authorized complete delivery does not need another pause. Build only the requested kit and applications.
- **Inspect letters and joins.** At actual intended sizes, check that modified letters retain their reading, counters and gaps stay open, and intersections have no accidental slivers, lumps or hairlines. In a vector drawing, distinguish true negative-space holes from white shapes painted over another fill. Compare optical weight, spacing and balance in black and reversed versions; adjust overshoot or reverse weight only when inspection shows a need, not by a fixed percentage. Preserve approved geometry unless its change is in scope.
- **Check the small version and context.** Inspect the actual render at 16 and 32 px when an icon/favicon is requested, plus the brief's real output sizes and backgrounds. A detailed wordmark may need a separately approved small-size symbol; never declare every mark suitable at 16 px. Compare silhouette and unintended readings against relevant references at equal scale without tracing them. A resemblance comparison is not trademark clearance.
- **Record evidence, not a score.** State the file/revision, sizes and variants actually inspected, defects repaired and checks still unperformed. A heuristic SVG audit or successful command is advisory and cannot certify visual quality, originality, font rights or a production master. Reuse the existing review budget and stop on a pass.

The complete reusable [Logo Design engine](assets/logo-design-engine/README.md) is bundled here: nine Python tools, fourteen reference chapters, templates, the searchable catalogue and fictional example renders. For requested vector work, `studio_logo.py probe` checks existing capabilities, `init` starts a project brief, and `build` produces concept/preview sheets, a presentation, advisory audit, SVG variants and optional PNG/web icons in a new output folder. The adapter records actual files and incomplete raster exports; inspect them before approval. Use native tools for finer control without modifying the pinned sources. Read chapters as needed, not the entire archive at intake. Upstream concept counts, compulsory loops, SVG-first defaults, visual examples and fixed mockups are reference material, not Studio decisions. The 1,432 third-party trademark SVGs are not licensed for redistribution with Studio: search returns their pinned links; a separately obtained original corpus can be hash-verified and connected for private reference study. The original `logo-design` remains an optional [native extension](../workflow-orchestrator/references/extensions.md); a separate installation is unnecessary for the bundled tools. Python and a suitable existing renderer are required only for executable outputs, with no automatic dependency installation.

## Direct production

When the user asks for the finished graphic itself and the brief already settles purpose, placement or size, the exact copy and enough about the look to choose (or names a direction), skip the direction menu: state the chosen direction in one line, produce it (generate, or compose on the exact-copy route), review the actual output and deliver, in one turn. Offer one alternative direction afterwards in a single line. This overrides the upstream activation sequence and Quick's direction-first step only for such a request; a request for concepts, copy or a prompt still stops there. Sizes and print defaults are in the [format and print presets](references/format-and-print-presets.md); an image too small for its placement follows [upscaling](references/upscaling.md) (measure, prefer a better source, enlarge before compositing text, a model licensed for paid work).

## Accessible format intake

For poster/flyer/static formats, use [ordinary-language format choices](../workflow-orchestrator/references/intake-and-reference-authority.md#format-choices-in-ordinary-language). This Studio conversational rule takes precedence over technical intake wording in the pinned source. First ask only the unresolved purpose: paper print, internet publication, both, or help choosing, with numbered options. For print, describe a whole printer sheet (A4), half a sheet (A5), or a larger two-sheet size (A3). For internet, describe a normal post or a phone story. Do not mix A4/A3 and unexplained pixels in one menu. Reuse known use, size and placement; a supplied exact pixel/physical specification bypasses this choice. Keep dimensions/export details backstage until the prompt or delivery needs them; explain technical terms when they help. Choosing a format is not generation permission or proof of print readiness.

## Technical diagrams

For a requested technical illustration or educational diagram, map the verified quantities and relationships before selecting shapes. A physical analogy is useful only when its parts and actions preserve those relationships; disclose its limits. Use purposeful detail at the actual reading size, consistent projection, attached connectors and correct occlusion; retain labels when they improve comprehension. The bundled [Anatomy toolkit](../../integrations/anatomy/README.md) preserves the requested raster/vector medium and existing generation permissions. An interactive or animated explanation goes to the motion owner's [technical explainer profile](../hyperframes-workflow/SKILL.md#technical-explainers-and-interactive-figures); choose the toolkit when its SVG, WebGL or 3D capabilities fit the task.

## Research and output boundary

For requested classroom posters, diagrams or educational graphics, use the [teacher profile](../workflow-orchestrator/references/teacher-workflow.md). Preserve the learning objective, approved wording, units, task labels and semantic relationships; inspect actual generated text and symbols. Keep integrated static ownership for a static-only request. Ordinary editable worksheets and lesson documents use the document/delivery route instead of automatic raster generation, and student-facing assets must not accidentally include teacher answer keys.

For a logo, logo system or visual identity, read the [brand identity profile](../workflow-orchestrator/references/brand-identity-workflow.md), especially logo/visual-system acceptance and stage handoffs. Own the integrated visual method, exact name/lettering, variants, typography, usage rules, prompts and inspected status. Reuse an accepted strategy; a logo-only request does not require full brand strategy, a brandbook or another intake. Marketing owns missing brand foundations and Delivery Pack owns the requested guide/file package. Distinguish raster concepts, reviewed digital assets and verified production masters; an SVG/PDF extension or mockup does not prove editable vector geometry, font rights or print readiness.

For substantive static work, apply the conditional shared [Research](../research-evidence/SKILL.md) gate and reuse unchanged evidence through the project. Keep the initial pitch free of source-heavy explanation unless the user asks for it or a concrete claim needs attribution. When model capability changes the recommendation, identify the exact model/surface/operation and research current official documentation; distinguish a native ChatGPT/Codex generation tool from API settings.

The source bundle and its release metadata are part of this plugin, so static-design users do not need to install another plugin or fetch the upstream repository. See [source provenance](source-provenance.json). The original source's own licence and all third-party rights stay distinct from this combined plugin's other materials.

For an artifact-specific prompt or observed unwanted repetition, false detail or face changes after an edit, use [periodic microtexture and preservation](../output-critic-iteration/references/periodic-microtexture-and-preservation.md) within this integrated static workflow. Preserve its single intake and shared repair budget; intentional patterns and stylization remain protected. Before returning an artifact-prevention prompt, remove exclusions for unreported patterns rather than expanding the correction into a blacklist.
