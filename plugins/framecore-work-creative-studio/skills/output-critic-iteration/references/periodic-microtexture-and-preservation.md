# Periodic microtexture and preservation

Conditional reference for the existing Studio image workflow. Its prompting interventions remain visually unbenchmarked.

Use when a brief mentions unwanted triangular, diagonal, diamond or cellular microtexture, when an inspected image exhibits suspicious repetition, or when a photographic person changes during an edit. For ordinary photographs, reuse the existing visual-subject craft checks. This reference does not add a review stage, retry allowance or generation permission.

## Classify the visible structure

Use the actual available image and identify its revision, viewing scale and reference role. Describe the affected region, material, direction and approximate scale relative to depicted objects. Do not invent a pixel period.

| Candidate | What distinguishes it |
|---|---|
| Periodic microtexture | Small recurring light/dark cells organize detail into a diagonal, triangular or diamond rhythm while object contours may remain intact |
| Large repeated patches | Whole image regions recur or shift; seams or discontinuous contours may be visible |
| False detail | Implausible specks, ridges, cracks or brittle sharpening can occur without regular repetition |
| Intended pattern | The brief calls for a weave, checker, halftone, lattice, scale pattern or an illustration of the artifact itself |
| Unresolved display effect | The appearance changes with preview size or zoom, or only a screenshot is available |

A pattern spanning unrelated materials strengthens suspicion, but a local defect can affect only skin, sky or foliage. Repetition alone is insufficient: consider whether it follows form, perspective, lighting, material and the approved design.

Dense droplets and sparks are not defective merely because they form bright clusters. A fabric repeat may be essential. A checkerboard visible behind an image may belong to a transparency viewer; establish whether it is in the actual file before prescribing an edit. Enlarging a thumbnail does not establish native-pixel inspection.

If no output is visible, discuss prompt risk or the user's report. Keep image-review status unverified.

## Preserve the person as well as the surface

For photographic people, make three concise judgments inside the existing review:

1. Does the relevant unwanted repetition remain?
2. Is the visible person photographically plausible at the actual crop and scale?
3. Are source identity and all protected properties preserved?

Do not collapse these into a smoothness score. A grid-free face can still look waxy; a convincing new face can still violate the identity lock. After a clothing or background edit, compare visible face and exposed skin with the actual source even if those regions were outside the intended change.

Naturally smooth skin, makeup, unusual bodies, asymmetry and polished studio lighting are valid. Do not invent aging, freckles, grain or exaggerated pores to make a person appear more real. Check only visible features. Intentional CGI, dolls, illustration and designed repetition keep their requested style.

An atypical body or disability is not by itself an anatomical error. Eye reflections need to agree with the scene's lighting and viewing geometry; they need not be identical.

If an essential source is missing, keep identity preservation unverified and request that source. A text description cannot substitute for a required likeness reference.

## Compile one relevant correction

Keep the existing brief and source bindings. Describe the desired material locally: where detail belongs, how it follows form, and what scale is appropriate. Add a narrow exclusion only when justified by the task. Do not concatenate an anti-artifact suffix with an existing equivalent constraint.

Keep required scene complexity. Reducing foliage, droplets, fabric pattern, person count or protected detail is a brief change requiring the user's choice. Do not silently use simplification as proof of repair.

For a localized edit, name the actual attached source, permitted region, desired surface and preservation set. A wording or mask boundary is not evidence that every other pixel stayed unchanged. Compare the result and protected regions afterward through the same reviewer.

## Optional context-isolation experiment

Use only when the supplied history supports a carryover hypothesis. Audit which images and roles actually entered the generation call. Similarity to an earlier image alone does not establish internal service state.

If the user chooses a fresh-context trial, carry the complete brief, exact copy, locks and clean necessary references. Keep earlier diagnostic notes outside the generator prompt. Never use “same as before” or mention an attachment absent from the new call. Do not silently discard an identity or product anchor because it is inconvenient.

Record the principal changed variable and the remaining shared authorization budget. A bundled change of context, reference and prompt can be a practical experiment, but cannot isolate which component caused improvement. One attractive output is insufficient to establish a reliable mitigation rate.

This trial remains inside Studio's existing repair budget. It does not reset attempts, authorize a new provider, establish a backend reset or guarantee clean output. If the actual host lacks the needed capability, report that limit.

## Acceptance and evidence

Use the existing review record and outcomes. Add the three judgments only where relevant; do not introduce competing status enums or mandatory numeric scores.

Accept a repair only for the inspected scope and stated use, with the target defect sufficiently reduced and protected identity, text, geometry, material detail and creative intent retained. Compare cumulative edits to the approved base. A cleaner surface with lost required detail fails preservation.

These are diagnostic and prompting design rules. Their contribution to generated-image quality has not been measured in a controlled Studio pilot. Current model behavior and exposed controls require current evidence. A visible grid does not identify a watermark, hidden architecture or generator; source packaging, instruction tests and image-quality improvement remain separate evidence.
