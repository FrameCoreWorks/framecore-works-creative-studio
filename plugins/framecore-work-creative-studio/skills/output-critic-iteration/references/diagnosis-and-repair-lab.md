## Separate evidence from cause

Record artifact ID/revision and original approved base; view size, crop and accessible references; observation location; affected requirement; confidence and unavailable evidence. Keep user reports separate from your own observations. If the image is absent, request it or provide a review method, never a fabricated pixel diagnosis.

| Statement type | Useful example | Common mistake |
|---|---|---|
| Observation | The supplied crop hides the last two required words | Calling the whole original unreadable from that crop |
| Requirement | All selected copy must appear verbatim | Rewriting the text to improve a score |
| Cause hypothesis | The available copy area may be too narrow | Claiming a model limitation without current evidence |
| Repair objective | Restore the two words while preserving the selected slogan | Rebuilding the visual concept automatically |
| Acceptance test | Inspect exact string and reading order at the intended size | Treating a prompt or script exit code as proof |

Research only the principle or current technical fact that could change this diagnosis, under the conditional research gate. A source supports a method; actual pixels support an observation. Accessibility guidance must be applied in its medium and context, not used as a blanket numerical poster certification. See the visual director's relevant typography guidance when needed.

## Choose the repair unit

1. Is a mandatory fact, identity, product feature or exact string wrong? Prioritize that mismatch over polish; keep the approved truth source visible.
2. Is the defect local with a usable original and supported edit route? Specify a bounded edit region plus a preservation set and test nearby dependencies.
3. Does the concept or information hierarchy fail across the artifact? Return to the direction/layout owner with the evidence; do not pile local fixes onto a broken system.
4. Is it only a missing measurement, inaccessible full-resolution source or delivery property? Ask for that evidence or retain Unknown. Do not render again to solve an inspection gap.
5. Has the same defect survived a repair? Compare against both previous result and original base. Change the causal hypothesis or method before considering another authorized attempt.

Treat one primary repair objective as focus, not a ban on related checks. A text-space repair can also affect product scale and safe areas; those causally linked properties belong in the acceptance pass. Preserve unrelated successful decisions.

## Worked poster diagnosis

**Hypothetical inputs:** poster r003, exact selected headline “Zostaw miejsce na dobry dzień”, approved blue product reference r002, portrait format. A readable supplied image hypothetically shows only “Zostaw miejsce na dobry”. The viewer must not infer that this actual image exists.

**Record:** critical copy failure at the headline's final line. Product silhouette, selected palette and main diagonal composition are declared locks from the brief, not yet a verdict that they match.

**Hypothesis:** the text zone cannot fit the current line breaks. **Proposed repair:** reflow the same full headline within a larger reserved text zone, preserving wording, product truth and concept. First test a layout specification; execute only if a supported image-edit operation and the user's authorization permit it. Do not substitute a coded text overlay for the Studio's requested integrated raster artifact.

**Acceptance:** compare all five words in order against the exact selected string, inspect diacritics, spacing and reading at intended display size, then check the product/copy separation and preserved locks. Delivery dimensions remain unknown unless actually measured. A technical pass does not resolve an unreadable word.

**Countercase:** the uploaded screenshot cropped off the word while the full poster includes it. Inspect the full image before prescribing an edit. The smallest repair may be to the preview or delivery framing, not the artwork.

## Worked product diagnosis

**Hypothetical inputs:** approved front product image and generated perspective still. The still appears to show an extra closure. The reverse side is not available.

**Record:** distinguish a visible extra closure from an inferred unseen construction. Compare the relevant reference area; if the angle hides the required evidence, label the suspected mismatch as a hypothesis. Do not “repair” the reverse side by guessing.

**Proposed action:** obtain the needed product view or select an angle supported by the supplied truth reference. If an actual visible discrepancy is confirmed, compile a scoped correction preserving camera position, material family and exact label. Check closure count, attachment, reflections and contact after the actual repair. Route generation through the image owner; retain static QA here.

**Countercase:** the second apparent closure is a reflection, intentionally consistent with the surface. Inspect highlight and reflection relationships before removing it. Stylization is not itself a defect.

## Test and retain scope

Use [the review record](../assets/review-record.md). Associate acceptance with the actual reviewed revision and dependency basis. When a source changes, use Delivery's [asset lifecycle](../../delivery-documentation/references/asset-lifecycle-and-dependencies.md); an old signature or manifest acceptance field is not a new inspection.

Choose the appropriate outcome: accepted for stated criteria; changes required with a bounded action; or insufficient evidence with the exact missing input. Do not issue an overall accepted verdict while a critical criterion is unverified. For an optional criterion, state the limit without blocking unrelated completed work.

Media boundaries remain unchanged: a still or thumbnail cannot prove temporal continuity, performance, lip-sync or audio quality. No listening, motion inspection, print certification or rights determination is supplied by this lab.
