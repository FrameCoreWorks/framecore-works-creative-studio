# Review, anti-slop gates and bounded repair

Owner: output-critic-iteration. Version: 0.1.0-dev.1. Updated: 2026-09-21. Stable synthesis from static-design QA/material diagnosis, Poster Creator quality loop and source-lock methods.

## Evidence first

This reference governs static-image evidence. For a supplied video, route temporal
review to [video-prompt-architect](../../video-prompt-architect/SKILL.md); for an
audio/song result, route capability-aware triage to
[audio-production-director](../../audio-production-director/SKILL.md). A frame or
screenshot supports only the static properties visible in it, not motion,
duration, lip-sync or audio. When relevant to a photographic/subject image, load
the applicable [identity, anatomy, wardrobe, product and capture checks](../../image-prompt-architect/references/visual-subject-craft.md#9-observable-anti-artifact-and-acceptance-checks)
and [cause-led corrections](../../image-prompt-architect/references/visual-subject-craft.md#10-cause-led-correction-loop).
Use those checks inside this owner's single diagnosis and repair budget; do not
start a second review workflow or impose realism on deliberately stylized art.

Establish which image/version is being inspected. Use the actual file where available, its intended viewing size and a full-resolution inspection for detail. A compressed screenshot can support hierarchy observations while leaving exact tiny text Unknown.

If no image is supplied, say so. You can analyze prompt risks or a user's description, but do not say “I see” or diagnose a specific pixel defect. A filename is not a visual observation.

Record important limitations: unavailable original, missing comparison source, unreadable text, unknown physical size, no alpha inspection, no color measurement. Do not mark a critical check not applicable to conceal missing evidence.

## Separate four questions

1. Does the artifact communicate the selected idea?
2. Are facts, text and protected source properties correct?
3. Does the actual craft support the viewing situation?
4. Does the file satisfy the requested delivery properties?

User taste and technical correctness are different. A deliberate dense collage may satisfy the concept while still failing a date check. A clean polished visual can fail because its idea is interchangeable. A readable raster cannot establish an editable master.

## Hard gates

| Check | What is inspected | When it blocks acceptance |
|---|---|---|
| Exact copy | Every required string, glyph, qualifier and approved break | Any required mismatch or extra misleading text |
| Claims | Visible offers, figures, marks and factual implications | Unsupported or invented material claim |
| References | Product geometry, label topology, identity, logo and other actual locks | Drift in a protected property |
| Concept | The selected mechanism and valued relationship | Replaced or missing core idea |
| Reading | First read, functional information, contrast, crop | Necessary information cannot be read in its use context |
| Method | Requested final artwork versus mockup/layers/overlay | Silent substitution of deliverable |
| Execution provenance | Applicable host/user tool, model and integration locks against actual execution evidence | Confirmed noncompliance; required compliance cannot be certified while provenance is unknown |
| Delivery | Measurable file properties relevant to intent | Required property missing or unknown |

One critical failure is enough. Do not average it away with a high aesthetic score. For a text-free design, copy checks may legitimately be not applicable; reference checks are not applicable only when no reference governs the task.

Carry the effective execution locks into review of a Studio-produced result. Do not infer its generator from appearance. Known use of a prohibited method blocks compliant delivery. Missing provenance means unverified, not evidence of misconduct or a made-up PASS. A missing model selector does not waive a required-model rule, and a prompt mentioning a model is not proof of its use. If an active mandatory selection cannot be established, report that capability limitation before claiming compliant execution.

This is not a reason to refuse useful visual criticism of an uploaded third-party poster. A reference or existing artwork need not have been generated by Studio's tool. State what is being assessed: visual craft may be reviewed separately while applicable production-method compliance remains unverified. Do not demand irrelevant provenance for every source image.

## Authored-design review

Examine the whole text-image relation, not a fashionable effect list.

- Specificity: identify the project-specific anchor.
- Hierarchy: describe what actually wins attention and whether that is intended.
- Composition: inspect alignment, grouping, relative scale, crop and use of space.
- Typography: inspect role separation, spacing, line endings, glyphs and functional reading.
- Material: check that texture/light belong to the represented surfaces and chosen process.
- Restraint: identify elements with no useful job or a system overburdened by effects.
- Context: check format, viewing mode, audience and relevant cultural associations.

“Human professional design” describes the quality sought, not the provenance of the image. Do not claim it was made by a human, guarantee undetectability or insist on handmade irregularities as proof.

For type-led work, test the word/form relationship rather than removing the word and demanding an image. For information-led work, clear retrieval can be the authorial achievement. Novelty is not mandatory for every functional item.

## Name observable failures

Useful: “The bright decorative ribbon interrupts the venue line and becomes the first read.”

Not useful: “It looks AI.”

Useful: “The container cap is wider than the supplied product reference, and its seam moved.”

Not useful: “Needs more realism.”

Useful: “The same cellular texture appears on skin, wood and cloth, flattening their material differences.”

Not useful: “The latent decoder is contaminated.”

Visible patterns do not establish internal model mechanisms. Compression, upscaling and screenshot rendering can also change appearance. Locate the defect and state its effect before choosing a cause.

## Material diagnosis

| Observed symptom | Distinguish from intended design | Focused repair |
|---|---|---|
| Repeated cells/dots on unrelated surfaces | Lace, bark, halftone, patterned fabric | Restore only the affected material while keeping its own detail |
| Uniform grid or tiling | Pixel art, gingham, layout grid | Remove accidental repetition where it violates the surface |
| Plastic skin or cloth | Stylization or smooth manufactured material | Restore appropriate local variation, not fake pores everywhere |
| Halos or doubled edges | Intentional outlines | Correct contamination while preserving silhouette |
| Lost fine structure | Deliberate flat fields or distant detail | Restore the specific lost structure, not global sharpening |
| Successive edit drift | Authorized reinterpretation | Return to the last approved base and isolate the change |

Evaluate artifact removal, surviving intended detail and preserved concept separately. Smoothing a bark defect into plastic fails if bark texture matters. Deliberate halftone should not be erased merely because repetition exists.

## Choose the smallest effective route

- Accept: all applicable critical checks pass with actual evidence; remaining preferences are not hidden failures.
- Scoped edit: local correctable defect, valid source and supported edit route.
- Recompose/rerender: the central mechanism or reading architecture fails, or a local route cannot preserve locks.
- Upstream loopback: missing fact, incompatible concept, unavailable reference or wrong target caused the failure.
- DTP handoff: fixed exact production requirements exceed the raster route.
- Hold review: missing or insufficient evidence.
- Generation failed: no usable output was returned; do not diagnose nonexistent pixels.

“One correction, one goal” means one primary diagnosis and test. Necessary dependent changes can be included explicitly. Moving a headline may require moving its subtitle; that is different from replacing the concept, image and palette without permission.

## Repair contract

State:

1. current asset and the evidence;
2. one primary defect;
3. what remains accepted;
4. permitted intervention and causal dependencies;
5. an observable test;
6. actual execution authorization and next step.

Do not initiate generation merely because this record exists. Respect current provider activation and user consent. A local exact text replacement requested by the user does not require asking again about that wording, but it does not authorize an external paid provider.

After a repair, check the target and every protected property plausibly affected. Compare cumulative edits with the approved base. Retain the previous artifact as a rollback point when files are actually available; do not claim version storage otherwise.

Use an explicit local budget: the baseline is not a correction; by default allow at most two authorized corrections for the same primary defect. This is a Studio workflow guardrail, not a measured optimum or a model limit. Each attempt records the changed hypothesis and observed result. The second cannot merely change a seed, adjective or palette.

If the same failure recurs, do not rename it to reset the count. After the budget is exhausted, stop that repair route and propose an upstream decision or production-method change. Do not launch it automatically. The user may deliberately authorize a new experiment with a genuinely different hypothesis; preserve the failed history and explain the tradeoff. Further execution still needs the current scope/authorization.

## Acceptance report

Use concise evidence instead of mandatory numerical scores:

“Nie akceptuję jeszcze wersji 02: data ma błędny miesiąc. Układ i tytuł są zachowane. Poprawka dotyczy wyłącznie daty. Test: zgodność wszystkich znaków w dacie oraz brak zmian pozostałych tekstów i kadru.”

If only a thumbnail was available:

“Hierarchia wygląda zgodnie z briefem, ale nie mogę zatwierdzić drobnego tekstu z tego podglądu. Potrzebny jest plik w pełnej rozdzielczości.”

These are teaching examples, not observations about a real file. The final verdict must be grounded in the actual inspected asset. A checklist or status view shows passed, failed or uninspected per criterion for the exact version reviewed; it adds no status that the evidence lacks ([presentation and interaction](../../pipeline-core/references/presentation-and-interaction.md#campaigns-and-qa)).
