# Teacher material methods

These are original authoring rules for the [teacher profile](teacher-workflow.md). Use only the parts needed for the requested artifact.

## Design from observable work

Write the objective as an action with a check: for example, identify a claim supported by a table and explain one limitation. Choose a task that produces that evidence. If the objective is reasoning, do not primarily score handwriting, speed or decoration. State prerequisites rather than assuming a grade label proves them.

A useful sequence is a small example, supported practice, an independent attempt and feedback. It is a choice, not a fixed lesson formula. Allow sufficient time for reading, transitions and responses; durations are estimates until tried. A short later retrieval task may revisit the same idea in a new setting. See [evidence and its limits](teacher-method-evidence.md).

## Minimum complete artifact

| Requested artifact | Include |
|---|---|
| Lesson/scenario | Objective, prerequisites, materials, realistic timed steps, exact teacher prompts, complete student content and an observable closing check |
| Worksheet | All necessary text/data/figures, clear numbered instructions, response space/format, matching answer key or open-response criteria |
| Quiz | Stated purpose, unambiguous items, correct options, explanations, point allocation and total; distractors should diagnose a misconception without trick wording |
| Game | Complete card/item set, setup, turn rule, success/end condition, sample turn and teacher resolution of ambiguous cases; no unavailable deck |
| Presentation | Actual slide wording, examples/data, teacher notes, pupil action and check; a heading list is an outline, not a finished presentation |
| Display/visual aid | One learning job, accurate labels/relationships, readable hierarchy and exact approved text; graphics must not reveal hidden answers unintentionally |
| Practical teacher advice | Context, concrete action, suggested wording, signs to observe and limitations; no unsupported guaranteed outcome |
| Guidance/career activity | Voluntary fictional scenario, respectful choices, reasoning criteria, reflection and practical information-gathering step; no diagnostic score |
| Teacher document | Intended use, editable fields, evidence/source status and separate planned/observed sections; no invented factual record |

Deliver answers outside student-facing content. If one combined file is requested, insert an explicit teacher-only section/page break and inspect that the distinction survives export.

## Vary support, retain the objective

Offer targeted changes, not a universal easy/medium/hard label:

- Shorter instruction chunks, an example, a word bank or a partially completed table.
- Spoken, written or diagrammatic response when the objective permits it.
- An extension requiring explanation, a counterexample or transfer, rather than only more items.
- A printable/no-device alternative where practical.

Record support used if reporting independent performance. Reading aloud preserves a sequencing/reasoning objective but changes a decoding assessment; say so. Do not assign learning-style labels, infer a diagnosis or promise accommodation compliance. Ask what access barrier matters rather than requesting a pupil's clinical file.

## Content and subject evidence

Use original stimuli and clearly synthetic datasets where real data are unnecessary. Do not give fictional information the appearance of an authentic survey, historical source or experiment. For sourced material, retain title/author, exact locator, date when relevant, permitted use and the claim it supports.

Curriculum alignment requires the user's jurisdiction, stage and requested version, an actually read official requirement and an explicit requirement-to-task/check mapping. A topical resemblance or Polish language is not alignment evidence. If access fails, mark alignment unverified; do not invent standard numbers, ministerial approval or legal duties.

Keep fact questions distinct from preference, inference and ethical discussion. Open tasks need defensible criteria and more than one acceptable answer when appropriate. Avoid stereotypes about ability, occupation, gender, family or background.

## Teacher review

Use this checklist inside the existing automatic output review, with the existing repair budget. It adds no gate or second scoring system.

1. **Objective:** each assessed task measures the declared action and uses introduced prerequisites.
2. **Completeness:** every text, datum, card, rule and instruction needed to participate is present or genuinely supplied.
3. **Correctness:** independently solve closed tasks; check units, totals, keys, option labels and reference numbers. For open tasks, identify criteria and acceptable alternatives.
4. **Wording:** instructions name what to do and how to respond; remove accidental ambiguity, unnecessary jargon and humiliating or coercive framing.
5. **Fit:** age/skill demands, reading load, duration and materials are plausible; support and extensions declare any changed objective.
6. **Evidence:** factual claims and claimed curriculum mapping have actual sources; synthetic examples and uncertainty are labeled.
7. **Rights/privacy:** original or authorized material, no identifying pupil data or copied commercial resources.
8. **Records:** plans, suggestions, observations and user-provided facts are distinguished; no invented completed events.
9. **Delivery:** student content, teacher notes, answers and scoring agree across revisions. Check actual page/slide breaks, labels, glyphs and overflow if an export exists.
10. **Status:** report source/content review, actual file inspection and classroom use separately. A checklist pass is not evidence of educational effectiveness.

Repair a material issue and check affected dependencies only. A passing draft is delivered without cosmetic rewrites. If a question cannot be answered from the stated inputs, fix the task or mark the missing input, not the pupil.

## Format and execution

Editable worksheets, lesson notes and textual slide content are document work, not automatically raster graphics. Use available document/presentation tools for requested files. If unavailable, provide complete content with an honest export-pending status; never invent a download link.

For requested static raster graphics with text, retain Studio's built-in image-generation and exact-copy rules. Generated text, symbols and educational relationships require actual image inspection. For an explicitly requested coded interactive activity, use the existing code-capable route, avoid pupil data collection by default, and distinguish code creation from executed interaction checks. Do not add dependencies, providers, uploads or publication simply because the topic is education.
