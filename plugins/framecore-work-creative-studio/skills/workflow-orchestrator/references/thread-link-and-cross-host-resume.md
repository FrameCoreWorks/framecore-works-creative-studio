# Thread-link and cross-host resume

Use when a user supplies a conversation URL, asks to continue work in another host, or requests a polished handoff. This is a retrieval procedure, not a hidden synchronization service.

## Resume from a link

1. Open the exact URL with the active host's available direct URL browsing/search tool. Do not search the public web using a private thread's text or client details.
2. Read the conversation body that the host actually exposes. Do not rely on a search snippet or title alone. Recover the goal, approved choices, rejected directions and reasons, exact copy/prompts, asset roles, research, current stage and unresolved questions.
3. Check whether attachments are independently accessible in this host. A readable conversation can contain previews or references to files that did not transfer.
4. State only material retrieval limits, then continue from the last accepted stage. Do not make the user repeat available context. Ask one question only if a decision or missing attachment blocks the requested next action.
5. If the host cannot open the link, say whether it was inaccessible, sign-in blocked, partial or not attempted. Then offer a compact handoff brief or request the missing excerpts/assets.

The user has confirmed that links to their shared conversations have worked with browsing/search in their ChatGPT Work and Codex workflows. Treat a supplied link as a useful first resume route and try it when the tool exists; access can still vary by host, sharing settings, link type and attachment availability.

## Portable two-way handoff

When requested, create a concise, complete handoff using [the handoff template](../assets/cross-host-handoff.template.md). Support both ChatGPT/Work to Codex and Codex to ChatGPT/Work. Include source links, exact approved copy and prompts, decision history, current evidence/rights state, asset availability, host/model conditions, authorizations and one clear next step.

Do not claim an automatic account/database sync. Do not place credentials, unnecessary private details, or unrelated user profile contents in a shareable handoff. Include the private workstyle preferences only when the user requests them. Label every missing asset and untested operation so the receiving host does not mistake a plan for execution.
