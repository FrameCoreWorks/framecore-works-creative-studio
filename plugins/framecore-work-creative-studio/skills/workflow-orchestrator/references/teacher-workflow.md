# Teacher Studio profile

Use this optional deliverable profile to create or revise classroom materials and teacher-facing documents. It uses the existing owners and one Project State. It adds no skill, agent, provider, menu or global state field.

## Entry and scope

A request to create a lesson, worksheet, quiz, educational game, presentation, class display, guidance activity or teacher document enters **creation**. Being a teacher or mentioning learning, pupils or school does not activate Learning Mode. An explicit request to learn how to create these materials uses the existing [mentoring method](learning-mode.md), with this profile as relevant domain knowledge. Reuse the current stage and accepted work.

Support subject teaching, early/primary/secondary education, classroom routines, social cooperation, career exploration, parent communications and teacher organization. Match age and actual prerequisites; age bands in examples are suggestions, not curriculum placement. A narrow request stays narrow: three questions do not require a full lesson pack.

This is a teacher-facing authoring workflow. It does not create unsupervised pupil accounts, diagnose learning needs, make consequential placement decisions, certify attainment or automatically grade identifiable pupils. Promotional work for a teacher's business uses existing Marketing/Ecommerce routes only when requested.

## Smallest useful brief

Reuse supplied facts. Ask one material missing question at a time; label low-risk assumptions instead of imposing a form. Establish only what changes the artifact:

- Material, topic, working language and intended use.
- Age/grade and relevant prior knowledge or skill.
- Observable objective: what pupils will do, explain, compare or make.
- Time, grouping, available equipment and access needs.
- Requested content/file format and whether teacher notes, answers or adaptations are needed.
- Jurisdiction, curriculum version and exact standard only when alignment is requested.

A usable task needs its source text/data/cards, instructions and a way to check the intended objective. Separate mandatory content from optional enrichment. For an unknown school policy, use a placeholder or ask rather than inventing a rule.

The [method evidence](teacher-method-evidence.md) supports selected design choices; it is not a current curriculum or proof that a lesson works.

## Work sequence

1. Define an observable objective and prerequisites.
2. Select one useful structure from [material methods](teacher-material-methods.md), then author complete content. Use the [activity bank](../assets/teacher-studio/activity-bank.md) for mechanisms, not a mandatory catalogue.
3. Solve each closed task independently; write criteria and acceptable alternatives for open tasks. Check that instructions and information actually permit those answers.
4. Add support and extension only as useful. Preserve the assessed construct or disclose how the objective changes.
5. Apply the [teacher review](teacher-material-methods.md#teacher-review) inside the existing bounded review loop. Content and answer checking stay with Copy Voice and Research Evidence. Output Critic reviews actual static images only; it is not a general pedagogy reviewer.
6. Deliver the requested content and any genuinely created files. Keep student material separate from teacher answers. Do not claim print, slide, accessibility or classroom QA that was not performed.

The optional [pack template](../assets/teacher-studio/lesson-pack.template.md) is a view of the current artifact, not an extra mandatory contract. Store its path/revision and dependent assets in the existing Project State. Content corrections propagate only to affected tasks, keys, slides and graphics.

## Privacy, authorship and records

Use fictional, non-identifying examples by default. Do not put pupil names, grades, health/disability reports, family details or identifiers into public research, external tools, examples or persistent profiles. Request only necessary de-identified context. Keep user documents in their authorized scope.

Create original explanations, task data and examples. A public listing is not permission to reproduce a worksheet, product title, distinctive exercise or paid material. Record rights for supplied text/images; access is not a reuse license.

Keep planned events separate from observed events. Never invent attendance, dates, interventions, outcomes, quotes, signatures or institutional approval. Missing report facts remain placeholders or Unknown. Teacher review and any required institutional process remain explicit.

Career tasks explore interests, criteria, information gaps and reversible next steps. Do not present them as aptitude/personality tests or predict a pupil's profession, earnings or admission. For factual advice about current qualifications or recruitment, verify the relevant official source for the jurisdiction.
