# Brand strategy, logo system and identity guide

Use for brand strategy, visual identity, a logo system, a logo usage guide (księga znaku), an identity guide (księga identyfikacji) or an explicitly requested rebrand. This is a deliverable profile within the existing Studio route, not a new skill or renderer. A logo-only request stays logo-only; reuse accepted strategy and do not force a brandbook, campaign plan or second design intake.

## Intake and shared state

Ask exactly one missing question per response and wait. Offer numbered choices and a free-text answer for that one decision. Reuse supplied facts, decisions and files; skip known questions and optional unknowns. Begin with the missing brand name, real offer, audience, practical goal or intended uses that would materially change the requested artifact. Do not present this contract or its internal template as a questionnaire. A complete brief goes directly to the requested stage.

Keep one Project State. Record the current stage, artifact IDs and revisions, accepted decisions, source/rights evidence, exact brand-name locks, unresolved choice and next action in the existing state. Use the [Brand Identity Pack](../assets/brand-identity.template.md) only when a multi-stage project or requested handoff needs it; it summarizes that state rather than starting another store. On resume, check current files and revision dependencies before continuing, without reopening answered menus.

Distinguish user-supplied facts, researched evidence, proposed strategy and Unknown. Research only the generalized question needed now through [Research Evidence](../../research-evidence/SKILL.md); reuse unchanged evidence. An originality check or public search is not trademark clearance, exclusivity or permission to use a font/reference. Do not invent market data, audience research, rights or competitor findings.

## Strategy acceptance

- The name and offer match supplied facts; positioning and values remain proposals until selected.
- The audience, use situation and desired perception explain the visual direction. Differentiation has a real basis or is labelled as a hypothesis.
- Voice principles and visual cues follow the strategy rather than generic style adjectives. A brand-only brief does not require a campaign CTA, launch plan or asset matrix.
- Missing research, rights or production requirements are explicit Unknown values, with blockers limited to the next requested decision.

## Logo and visual-system acceptance

- Preserve the exact brand-name spelling, diacritics, selected wording and approved mark geometry. Present materially distinct directions when requested; do not copy a reference logo or treat resemblance search as clearance.
- Define only the requested useful variants: primary lockup, alternate orientation, symbol/wordmark, monochrome and reversed versions as relevant. Variants retain the selected identity and correspond to identifiable source revisions.
- Define clear space using an explicit reference unit from the mark. Minimum size is proposed until checked at the actual target sizes and contexts; inspect silhouette, counters, strokes, exact lettering and legibility. Never invent measured test results.
- Record palette values, hierarchy, typography and imagery/icon/layout rules that are actually part of the system. Font names, availability, licence/embedding limits and fallback status travel with the files. State RGB/HEX values as defined digital values; CMYK values and print readiness require the actual conversion/profile and production checks, otherwise Unknown.
- Distinguish an inspected transparent asset from a white-background preview. Review actual full-colour, monochrome and reversed variants where supplied, without claiming that one inspected image proves every variant works.
- An image generator's raster is a concept or reviewed digital raster. An SVG with an embedded image, automatic trace or PDF wrapper is not proof of an editable vector master. Claim editable vector only after inspecting actual vector geometry, text/font handling, external dependencies and rendering; disclose embedded raster or live-font dependencies. Do not rename a PNG to imply SVG/PDF production work.
- A production master requires verified properties appropriate to the requested use: correct geometry and lettering, matching variants, bounds/viewBox or page size, colour basis, font/outline status, actual editability and successful opening/rendering. Outstanding printer, font or export checks remain explicit. A logo mockup is an application preview, not the master.

## Guide, applications and delivery acceptance

A **Logo Guide** documents the exact selected mark and revision, lockups/variants, construction or proportion rules where supported, clear space, tested/proposed minimum sizes, colours, type/font handling, background rules and concrete prohibited alterations. Do not fabricate construction geometry from a raster.

An **Identity Guide** adds the accepted strategy, voice principles, visual language, palette/type hierarchy, photography/illustration/icon/layout rules and requested applications. State the requested scope: a logo guide alone is not a complete identity guide. Propose relevant application types only when unresolved; use the requested count and existing use contexts. Do not force four applications onto a logo-only request. Each application references the same selected logo/system revisions; adapt layout to its purpose without inventing a new mark.

Produce real requested files only with actual host capabilities and scoped authorization. Record document content separately from visual layout and validated export. For each file, list actual path/access, format, revision, intended use and status: specification, concept, reviewed digital asset or verified production master. Open/render exported documents when possible and state the inspected scope; a filename, extension or a successful ZIP operation does not prove visual or production quality. Without a suitable vector/layout/export tool, deliver the requested feasible concept/specification and a precise remaining-production handoff instead of promising nonexistent masters.

Reuse the [asset lifecycle and dependency contract](../../delivery-documentation/references/asset-lifecycle-and-dependencies.md). A changed accepted logo, palette or font revision flags dependent applications and guides for bounded reassessment; keep unrelated accepted artifacts intact. Deliver only available, current, accepted files as final, and label provisional content. Keep unresolved rights/technical checks and the next action concise. External generation, uploads, paid services and publication remain separate scoped operations under Studio authority.
